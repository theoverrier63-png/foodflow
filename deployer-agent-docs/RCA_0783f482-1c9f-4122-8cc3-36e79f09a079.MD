```
Step #7 - "eas-update": [EAS_LOG] Checking for dynamic config files...
Step #7 - "eas-update": [EAS_LOG] ERROR: No app.json, app.config.js, or app.config.ts found!
```

## Root cause
The deployment is pinned to the **Expo/EAS template** (`expo_mongo_base_image_eas`). Its `eas-update` step (which lives in the deployer binary and **cannot be edited or skipped per-app**) requires an Expo config file and then Metro-bundles an Expo app.

But the **frontend source has been rewritten into a pure web app**. Verified in the pulled source (`/app/scratch/frontend`):
- `package.json` name = `leray-pointel-web`; deps = `react`, `react-dom`, `react-router-dom`, `lucide-react`, `clsx`; devDeps = `vite`, `@vitejs/plugin-react`, `tailwindcss`, `typescript`. **No `expo`, no `react-native`, no `metro`.**
- `vite.config.ts`, `index.html` (`<script src="/src/main.tsx">`), `postcss.config.js`, `tailwind.config.js`, `tsconfig.json` present — a Vite SPA.
- `src/main.tsx` renders with `ReactDOM.createRoot` + `react-router-dom` `BrowserRouter` — a browser app, not a React Native entry.
- **No `app.json` / `app.config.js` / `app.config.ts` anywhere in the tree** (confirmed via `find`).

The backend `docker-build` lane succeeded; only the EAS frontend lane fails, because the source is no longer an Expo project.

This is an **architecture/template mismatch**, not a one-line bug:
- Adding a stub `app.json` would NOT fix it — with no `expo`/`react-native`/`metro` deps and a Vite `main.tsx` entry, `eas update` would then fail at Metro bundling instead. There is no single source file edit that makes the Expo EAS template publish this Vite web app.

## Resolution (decision required — pick one)
1. **If this app is meant to be a web app now:** it must be deployed on a **web/kubernetes-frontend template**, not the Expo EAS template. The current deployment job cannot build this source. This requires re-provisioning the deployment on a web template (platform-side).
2. **If this app is meant to stay a mobile Expo app:** revert the frontend rewrite — restore the Expo project (`app.json`/`app.config.js`, `expo` + `react-native` deps, Expo Router/entry) so the EAS lane has a valid Expo app to bundle.

## Notes
- Do NOT simply retry the deploy — it will fail identically at `eas-update`.
- `.env` still carries `EXPO_PUBLIC_*` vars plus a new `VITE_BACKEND_URL`, another sign of a half-migrated frontend.
